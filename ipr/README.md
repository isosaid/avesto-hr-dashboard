# Авесто ИПР

Платформа «Развитие руководителей» (индивидуальные планы развития) холдинга «Авесто Групп»: кабинеты HR-директора, куратора и руководителя.

**Открыть:** https://isosaid.github.io/avesto-hr-dashboard/ipr/ (или https://isosaid.github.io/avesto-ipr/ после переноса в отдельный репозиторий)

## Два режима

**Здесь включён режим базы:** проект Supabase `avesto-hr` (тот же, что у дашборда обучения). Учётная запись настроена для `hr@audit.test`.

| Режим | Когда | Вход |
|---|---|---|
| Демо | `SUPABASE` в `index.html` пустой (по умолчанию) | любой пароль, кабинет выбирается по email |
| База данных | в `SUPABASE` указаны URL и anon key проекта Supabase | пароль проверяет Supabase Auth, роль берётся из таблицы `ipr_profiles` |

Учётные записи:

| Кабинет | Логин |
|---|---|
| HR-директор | `hr@audit.test` |
| Куратор | `curator01@audit.test` |
| Руководитель | `long@audit.test` |
| Суперадмин | `superadmin@audit.test` |

## Подключение базы (Supabase, ~10 минут)

1. https://supabase.com → **New project** (бесплатный план подходит). Запомните пароль базы.
2. **Authentication → Users → Add user → Create new user** — для каждого email из таблицы выше: задайте пароль, включите **Auto Confirm User**.
3. **SQL Editor → New query** → вставьте `supabase_setup.sql` → **Run**. В конце должно вернуться 4 строки.
4. **Project Settings → API**: скопируйте **Project URL** и **anon public** key.
5. В `index.html` найдите строку `const SUPABASE = { url: "", anonKey: "" };` и впишите их:
   ```js
   const SUPABASE = { url: "https://xxxx.supabase.co", anonKey: "eyJ..." };
   ```
6. Сохраните и закоммитьте — GitHub Pages обновится за минуту.

Anon key публичный по замыслу Supabase: доступ ограничен политиками RLS, каждый пользователь видит только свою строку профиля. Ключ **service_role** в файл не вставлять.

### Что работает в режиме базы

- вход по email и паролю, ошибка «Неверный email или пароль»;
- кабинет по роли из базы; чужие кабинеты и раздел суперадмина закрыты;
- сеанс сохраняется после перезагрузки и продлевается автоматически;
- смена пароля (проверка текущего, ≥ 10 символов, не совпадает со старым); остальные сеансы при этом закрываются;
- `must_change_password = true` в `ipr_profiles` — при входе сначала откроется смена пароля;
- «Выйти» и «Выйти на всех устройствах».
- «Личные данные» (аватар справа вверху): ФИО и телефон сохраняются в базе, смена email — с текущим паролем; фото хранится в этом браузере.

Новый пользователь: добавьте его в Authentication → Users, затем строку в `ipr_profiles` (по образцу из `supabase_setup.sql`).

Данные кабинетов (планы, задачи, оценки) пока генерируются в браузере: внесённые, изменённые и удалённые оценки видны сразу на всех страницах, но после перезагрузки страницы возвращаются к исходным.
